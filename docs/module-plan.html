Just Neko模块规划 · 需求整理 · 拓展方向

2026-11-18 · 基于首个提交时的原型整理；同日完成 M1 地基重构后更新

更新：方向已经定了：要按对外发布做、TTS 本地和云端都做、默认用本地模型、提前为多平台留好接口。M1 地基重构已经完成，结构和扩展方法见 README 的「代码结构」。下面是重构前的判断，保留作对照。

现在的原型已经证明三件事能成：透明置顶的 Live2D 桌宠、流式 AI 聊天带表情、行为驱动的动作绑定。接下来最大的问题不是缺功能，而是所有 AI 逻辑都塞在 ChatWindow.SendAsync 里：拼提示词、选服务、解析表情、推气泡、切动作全在一个方法里完成。语音、视觉、记忆、习惯都要从「一次交互」这个入口进来，所以我建议下一步先花一个小里程碑把交互编排层抽出来，再按 语音 → 视觉与记忆 → 习惯 → 插件 的顺序往上叠。

2. 目标架构

我按「谁依赖谁」分成五层。上层只通过事件和接口用下层，Godot 相关的代码只出现在外壳层和表现层，这样编排、AI、记忆这些都能脱离 Godot 单独测试。

外壳层Shell · Godot
桌面窗口透明置顶、穿透、拖动、多屏夹取
交互界面聊天窗、气泡、属性面板、设置
平台接口IPlatformServices：Windows 已实现，其他平台留好口子
系统集成托盘、单实例、开机自启、全局快捷键

Live2D 渲染gd_cubism、模型加载、退回预览猫

核心：一次交互怎么走

无论是你发消息、桌宠定时开口，还是让它看屏幕，都走同一条管线。每次交互有自己的 ID 和取消令牌，用户输入可以打断习惯触发的交互，停止时网络、TTS 队列一起取消，这一轮迟到的事件直接丢弃。

① 触发用户消息 / 点击 / 习惯到期 / 看屏幕。能本地完成的反应（点头、跟视）直接交给表现层
② 准备输入任务模板 + 角色设定 + 长期指令；按需检索记忆、附上截图
③ 路由按任务选服务：文本、视觉、Embedding、TTS 可以各自绑定
④ 边收边演文字进气泡，表情动作给角色，完整的句子进 TTS 队列
⑤ 写回进近期对话；「请记住」直接保存，其余在后台提取候选记忆

第一步要拆什么

从哪里拆拆成为什么
ChatWindow.SendAsync 里的提示词拼接、历史、路由InteractionOrchestrator + PromptBuilder + ConversationHistory语音、习惯、视觉都要复用这条管线，不能每加一个入口就复制一遍
静态 ChatClient实现 IChatClient 的 DemoChatClient、OpenAiCompatibleChatClientREADME 里已经定了接 Microsoft.Extensions.AI，工具调用和视觉都靠它
EmotionStreamDirectiveParser：在流的任何位置拆出 [emotion]、[motion] 等标签，输出事件TTS 要按句切分，表情要能跟着句子变
DesktopPet 里的行为切换PetBehaviorMachine，订阅编排层的事件新增「说话中」「看屏幕」「被摸头」等状态时不用改窗口代码

F11角色包导入与分享角色包P1一个 zip 包含模型、设定、表情映射、动作绑定，导入即可切换角色

非功能需求

方面要求
资源占用桌宠一直挂着，待机时 CPU 要尽量低，内存要有上限，具体数值待定；已经限到 30fps，后续可以在静止时进一步降帧

隐私截图默认只用于当前交互；记忆只存本机，能看、能改、能删；外发的内容在设置里说清楚
容错网络请求不卡界面，失败能重试并给出看得懂的提示；Live2D 不可用时退回预览猫（已有）
可观测每次交互记一条结构化日志：触发源、服务、首字延迟、总耗时、是否取消、失败原因
发布质量在全新的中文 Windows 上字体和编码正确，中文字体随包带，读写一律 UTF-8

4. 路线图

M0 · 原型 已完成

桌宠外壳、Live2D、流式聊天带表情、行为动作绑定、气泡、属性面板。

M1 · 地基重构 已完成

拆出纯 C# 的 core 类库；交互编排器、IChatClient、指令解析器、分层动作、自主活动框架；默认本地 Ollama；设置持久化 + DPAPI；平台接口；交互留痕。
验收：原有的聊天、气泡、角色属性回归全部通过；停止、迟到事件、优先级、错误提示、设置和 Key 读回都有自动化测试覆盖（测试留在本地 AI_Temp，不入库）。

M2 · 会说话 下一步

TTS 适配器（本地和云端都做，设置里切换）、按句切分的播放队列、按音量驱动口型、停止即停声。
验收：F3、F4 达标；连续 20 轮对话没有声音错位或残留。

M3 · 看得见、记得住

单帧视觉；SQLite 存记忆，加向量检索；「请记住」直接保存，其余后台提取候选；记忆管理面板。
验收：F6、F7 达标；删掉的记忆不会再被检索出来。

M4 · 有自己的节奏

习惯调度接进同一个入口；视线跟随、悬停、摸头这类本地反应；空闲检测。
验收：F8、F9 达标；习惯触发和用户输入同时发生时，用户输入优先。

M5 · 能干活、能换角色

工具调用 + MCP 插件 + 权限面板；角色包格式 v1，支持导入导出。
验收：番茄钟插件跑通；第三方角色包导入后能直接用。

M6 · 能发出去

托盘、单实例、自启；安装包与自动更新；首次启动引导；发行版 Live2D 扩展；许可证梳理。
验收：在全新中文 Windows 上，从安装包解压后一次跑通。

5. 未来拓展方向

下面这些不在当前路线图里，但架构上提前留好口子，以后加起来不用推倒重来。

🎙️ 语音输入

按住说话或唤醒词，ASR 结果作为一种触发源进编排器。M2 的音频管线可以直接复用。

💞 情绪与关系

持续的心情值和亲密度，影响语气、待机动作和习惯频率。记在记忆层，由编排层读取。

🎮 陪伴场景

识别正在玩的游戏或在用的软件，切换到陪玩、专注、摸鱼提醒等模式。基于感知层的活动窗口。

🧩 角色包社区

角色包加上签名和版本号，做分享和一键导入；习惯和工具权限在导入时逐项确认。

🗣️ 角色专属音色

用本地语音克隆给角色配固定音色，和角色包绑在一起分发。要先确认声音授权。

👯 多角色同屏

两个桌宠互相对话。编排器按角色隔离上下文，表现层支持多个实例。

📱 跨设备

手机端提醒、远程跟桌宠说话。需要一个轻量的同步服务，放到最后再考虑。

🔧 自我进化

拿交互留痕定期复盘：哪些回复被打断、哪些习惯总被关掉，据此调提示词和默认配置。

6. 风险

风险影响建议
Mao 是 Live2D 官方示例模型示例模型有使用条款，不能当自己的角色对外发布对外发布前换成自有或已获授权的模型；仓库里本来就不放模型
Cubism SDK 发行许可商业发布有营收门槛和发布许可要求确定发布形式后查一遍官方许可条款
gd_cubism 是社区项目，还自带 R5 补丁升级 Godot 或 SDK 时可能坏锁定版本；补丁和编译脚本已经在 tools/ 里，保留好
截屏和记忆涉及隐私用户信任问题默认不落盘、看屏幕要明确触发、记忆可见可删
云端模型限流和费用习惯触发太频繁会烧钱或被限流习惯默认冷却保守一点；按服务统计调用次数
